Open Source · Self-hosted · Multi-provider

把模型、知识库与本地执行，
放进同一套系统。

Nexora 是一个开源、可自托管的 AI 工作台，由三个项目组成： Nexora 负责平台内核，NexoraCode 把执行落到你自己的电脑， NexoraLearning 把教材变成可追踪的学习路径。 三者共用同一份账号、模型与权限配置。

01 三个项目

从平台内核，到本地执行，再到学习路径

Nexora 不是一个大而全的应用，而是一组边界清楚的组件：内核负责模型、知识、权限与观测； 本地执行体负责真正碰你的文件与终端；学习系统负责把学习过程变成可追踪的路径与反馈。 你可以只用其中一个，也可以把它们装在同一台机器上。

Nexora

Platform Core / ChatDBServer

Nexora

统一接入模型、组织知识与工具的对话内核。模型、向量库、邮件、搜索、网盘都是可替换组件， 因此你可以只跑内核，也可以把每一项换成自己的实现。

  • 目录ChatDBServer/
  • 启动python server.py
  • 运行时Flask · Python · SQLite

01

多 Provider 统一接入

DashScope、OpenAI、Volcengine、Ollama、vLLM 走同一套接口，模型参数与超额策略集中维护。

02

知识库与 RAG

文本与文件向量化存入 NexoraDB，支持知识库管理、知识图谱与协作编辑。

03

工具按需注入

工具选择权交给模型，不再一次性注入全部工具；Auto / Force 模式可切换，长会话更省 Token。

04

记忆与上下文

会话记忆、长期记忆与上下文预算统一管理，跨会话继续同一件事时有据可依。

05

权限与可观测

用户、角色与模型可见性按 ACL 分配；Token 消耗与对话日志按用户、模型、时间维度统计。

06

邮件与网盘绑定

NexoraMail 账号与平台用户统一绑定，注册、找回与通知走同一条链路；文件走 NexoraNetdisk。

RAG 知识图谱 长期记忆 工具路由 PAPI 密钥 笔记 Token 观测 模型榜单

03 本地执行体

Desktop Runtime / Windows

NexoraCode

跑在你自己电脑上的执行体。Agent 循环、模型配置与工具权限全部留在本地： 它读你的文件、跑你的命令、渲染你的页面，而危险操作需要你点同意。

  • 目录NexoraCode/
  • 形态Windows 桌面应用
  • 通信WebSocket · 设备配对
  • 状态NexoraCode V4.0
Local

你的电脑

本地配置 Provider 与模型，Agent 循环、文件读写、终端与浏览器工具都在本机执行。

Cloud · Identity Only

Nexora 云端

只做身份校验与即时转发：配对码、连接和等待中的请求都在内存里，不持久化会话内容与执行事件。

Remote

手机与网页

同一账号登录后，在网页 Projects 或移动端侧栏选择在线电脑，发起新任务或继续已有会话。

01

本地工具链

Shell 与终端、文件读写、代码扫描、浏览器页面渲染与操作、图片搜索、进程管理。

02

权限与自动审批

按工具与路径授权，敏感操作弹窗确认；常用动作可交给自动审批策略，少打断心流。

03

上下文压缩

按模型窗口预算本地压缩已完成轮次，原始历史不删除，可用 local_context_search 回溯。

04

远程任务与回放

每个请求带固定 request_id，重试不会重复执行；断线重连后可补取执行事件。

05

本地插件

从 plugins/ 加载受信任插件，可注册工具与自有面板，数据与服务端分开存放。

06

错误自动重试

长任务遇到瞬时失败自动重试，任务中断会明确标记，不会静默丢失上下文。

06 设计取舍

这几条取舍决定了 Nexora 的样子

功能可以加，取舍不能含糊。下面四条贯穿内核、桌面端与学习系统。

01

数据留在自己机器

文本、向量库与文件默认本地存储，仅在模型调用时访问；云端只承担身份与转发，不长期保存会话内容与执行事件。

02

Provider 可替换

项目不提供模型，只提供适配层。换个 Provider 不需要改业务代码，模型可见性也能按用户或角色分配。

03

工具按需注入

不一次性把所有工具塞进上下文。模型先选工具，再取定义，长会话因此更省 Token，也更少被无关工具干扰。

04

执行必须可解释

危险操作要审批，任务带请求标识与执行日志，压缩过的历史仍可检索。宁可多一步确认，也不让系统静默改动你的机器。

07 快速开始

先跑起来，再决定接哪些组件

内核是第一个需要启动的组件。用户账号在 ChatDBServer/data/user.json 配置，模型自行用 Ollama 或云厂商提供。

平台内核

Nexora

克隆仓库并启动内核，浏览器打开输出端口即可进入工作台。

git clone https://github.com/Himpq/Nexora.git
cd Nexora
pip install -r requirements.txt

cd ChatDBServer
python server.py
本地执行体

NexoraCode

下载桌面端安装包直接使用；从源码运行时，先在设置里配置 Provider。

cd NexoraCode
pip install -r requirements.txt
python main.py
学习系统

NexoraLearning

单独启动学习服务，并在内核配置中填入它的地址与 API Key。

cd NexoraLearning
pip install -r requirements.txt
python main.py
