# 方案：首页功能宫格 + 随笔 + Learning 枢纽

状态：已评审通过，待实施。第一批范围 = 首页宫格改造 + 随笔（本地持久化）；Learning 枢纽页后置到比赛内容接入时实现。

## 一、主壳纪律（解决"全能但会乱"的根本规则）

主壳永远只有四层，新功能先分诊再落位，不再出现"入口没地方放"：

| 层 | 职责 | 规则 |
|---|---|---|
| 主列（MainChat） | 只放对话 | 任何非对话内容不得嵌入主列 |
| 首页宫格 | 高频功能直达 | 空态问候区下方，2 列卡片 |
| 侧栏抽屉 | 全量导航 | 顶部功能行清单 + 最近对话/知识库 + 紧凑账户行 |
| 全屏页容器 | 功能空间（MailPage 模式泛化） | 顶栏返回 + 分段/筛选 + 列表 + 详情 |

新功能分诊口诀：**对话型**走 `conversation_mode` 进主列（如 AI 辅导）；**内容库型**进全屏页容器，并按需在首页宫格加卡片、侧栏加功能行。永不上底部导航栏。

## 二、首页空态改造（换血不换骨）

QuickActionGrid 的 Grid 骨架、按压态、交错入场动画全部保留，仅替换卡片内容与点击行为：

```
晚上好，Himpq
今天想让我帮你做点什么？

┌────────────────┬────────────────┐
│ ✎ 记一条随笔      │ ✉ 邮件          │
│ 想到就写，自动保存  │ 收件箱 · N 封未读 │
├────────────────┼────────────────┤
│ ▤ 学习中心        │ ◫ 知识库         │
│ 教材 · 辅导 · 统计  │ 团队知识，问答可引用│
└────────────────┴────────────────┘

[输入栏........................]
[✦ 帮我写作 | 知识库问答 | …]  ← 提示词模板降级为小号横滑芯片
```

### 卡片行为

- **记一条随笔**：点击 → NotesPage 直接进入新建编辑态（一跳直达，解决"随笔藏太深"）。
- **邮件**：打开 MailPage，卡片带未读数角标（`GET /api/mail/me/status` 现成）。
- **学习中心**：打开 LearningHubPage（枢纽页，见第四节）。
- **知识库**：切换侧栏知识库视图（与现有 setSidebarView 打通）。

### 现有 4 个提示词芯片的降级

- 深度思考 / 联网搜索：本质是生成参数，与设置页 toggle 重复 → 收敛到输入栏参数区（后续），不占首页。
- 帮我写作 / 知识库问答：本质是 prompt 模板 → 降级为输入栏上方小号横滑芯片行，点击填入输入框（逻辑不变，位置与尺寸变化）。

### 数据模型调整（AppConfig.ets）

- `QUICK_ACTIONS` 拆为两套：`PROMPT_ACTIONS`（模板类，kind='prompt'，进输入栏芯片行）与 `FEATURE_ENTRIES`（kind='feature'，进首页宫格，含 id/label/hint/icon/action 路由标记）。
- `QuickActionGrid.ets` 改名或演进为 `FeatureGrid.ets`，卡片支持角标（邮件未读数）。

## 三、随笔（Notes）设计

### 定位规则（与知识库的切分，写死）

| | 知识库 | 随笔 |
|---|---|---|
| 本质 | AI 的基础设施（RAG 引用源） | 个人的快速捕捉 |
| 形态 | Markdown 编辑器、置顶/菜单 | 纯文本/轻 Markdown，打开即写，无菜单 |
| 标题 | 手动命名 | 首行自动截取，不用起名 |

### 页面结构（复用 MailPage 骨架）

顶栏（返回 / 标题 / 新建）→ 搜索框 → 笔记卡片列表（首行摘要 + 更新时间，支持置顶延后）→ 编辑详情态（自动聚焦，失焦/返回即保存）。

### 数据层

- 第一版**本地持久化**：PreferencesUtil 或关系型数据库，AppState 挂 `noteList/noteLoading/noteError`（镜像 knowledge 模式），零服务端改动、离线可用，比赛演示最稳。
- 接口层按 ApiService 形态预留（NotesService 形状），后续需要跨设备同步时补 `POST/GET/PATCH/DELETE /api/notes` 换后端实现，UI 不动。
- 侧栏新增功能行「随笔」负责浏览入口；首页卡片负责捕捉入口。

## 四、LearningHubPage 枢纽（比赛内容接入时实现）

- 侧栏功能行 + 首页卡片双入口，均指向 LearningHubPage。
- 枢纽内为子入口卡片区：**教材阅读 / AI 辅导 / 学习时间统计** + 最近学习记录。
- AI 辅导若为对话型：不新建界面，走会话 `conversation_mode` 进主列（服务端字段现成）。
- 生态内加任何子功能都在枢纽页内扩展，主壳不膨胀。

## 五、实施顺序

1. `AppConfig` 数据拆分 + `FeatureGrid` 宫格改造 + MainChat 回调分发 + 输入栏上方芯片行。
2. 随笔：AppState 本地持久化 + NotesPage + 侧栏功能行。
3. 邮件未读角标接入首页卡片（可选，依赖 status 接口联调）。
4. LearningHubPage 占位卡片在宫格预留，比赛时填充真实内容。

## 六、双端同步注意

NexoraApp（鸿蒙）与 NexoraApp_Android（ArkUI-X）的 `entry/src/main/ets` 为镜像结构，本方案实施时两端同步修改；EntryAbility / LiveViewController / EntryBackupAbility / 资源与构建脚本存在平台差异，同步时跳过。
